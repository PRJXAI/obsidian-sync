# Threat model

## Boundaries

HTTP clients/devices/agents and all document data are untrusted. Tailscale reduces exposure but never replaces authorization. The OS/service UID, private backend directories/parents, operator configuration/secret files and storage provider are trusted. Root/service-UID compromise, provider write-credential compromise, a malicious provider/kernel/hypervisor, disk loss and stolen backups require external controls and independent encrypted backups.

Self-hosted LiveSync authenticates using a principal UUID and random 256-bit key as Basic credentials; Bearer keys share the verifier. SQLite stores SHA-256 digests, not human passwords. Client E2EE passphrases/security seeds remain client-side and are distinct from authentication. A compromised write device can make authorized malicious edits inside its vault; revision immutability, revocation, retention and verified backups support recovery, not prevention of all authorized harm.

## Controls and residual risks

| Threat | Control / residual risk |
|---|---|
| Cross-vault access | Alias resolves to a vault grant; document bodies, historical revisions, feeds, bulk APIs and checkpoints re-authorize against current grants. Negative tests cover wrong-vault, read-only, revoked and malformed Basic credentials. No direct object-store/file access for agents. |
| Credential leaks | Generated keys, separately revocable per device; fixed first-party-only tracing, no request paths/bodies/tokens/signed URLs/raw error sources. `issue` explicitly prints its new secret once to trusted operator stdout; protect that output and exclude one-shot key export from centralized logs. |
| Privilege escalation / reset | No implicit `_admin`, global configuration/user/security mutation, arbitrary alias creation or physical purge. A separate local bootstrap capability can reset only its granted database. Reset retains old bodies/revisions/checkpoints, archives old grants, retires active old-generation grants, inherits charged quota and is capped at 16 generations. Ordinary credentials cannot reset. |
| Conflicts / lost writes | Genuine persistent revision trees, CouchDB deterministic winner, retained losing branches, atomic DAG/head/sequence/quota publication, branch-specific tombstones. Imported duplicate revision preserves first body; fresh upstream E2EE ciphertext is NOT a conflicting new revision. Contradictory ancestry fails. Core explicit idempotency keys remain payload-bound. |
| Interrupted commits / old writers | Immutable bodies durable/verified before references; SQLite FULL/WAL immediate transactions; process lock held through canceled DB tasks. Epoch-bound cursors reject stale resets. Reset retires old grants, fencing late uploads; previously reserved bytes remain charged. No distributed writer or exactly-once external-effect claims. |
| Filesystem traversal/symlink race | Couch document IDs are NOT filesystem paths and may legally contain slashes. Blob addressing uses generated vault/object UUIDs only. Descriptor-relative no-follow walks, exclusive staging, fsync/file-directory durability and no-clobber publication; active directory-swap tests. Parent directories must remain trusted. |
| SSRF / object-store misuse | Provider endpoints, bucket/prefix and credential paths come from server configuration, never clients. Remote HTTPS; S3 redirects/proxies disabled and loopback HTTP opt-in only. Provider conditional-create probes fail startup when guarantees fail. Native cloud credentials/lifecycle require separate validation. |
| Resource exhaustion | Typed byte/document/batch/response limits plus pre-parse structural-token and conservative aggregate JSON working-set budgets (byte limits alone do not bound DOM allocation); 64 sockets with 90-second lifetime, 8 default execution slots, 16 normal admissions with a 1-second bounded queue, 32 bounded feed admissions, finite long-poll/body/operation/drain deadlines, per-principal/global token buckets with bounded registry. Waiting feeds release execution slots to preserve write capacity. Two-slot CPU pool and bounded DB/fs pools retain permits through canceled blocking tasks. Configured limits are capacity policies, not a guarantee against every availability attack. |
| Metadata/storage growth | Minimum charged blob allocation, node/leaf/ancestry/local-checkpoint/sequence/job caps, cumulative reset allocation and reset-generation cap. No automatic final GC or finite retention. Quota exhaustion fails closed; archived/orphaned content stays charged. Dedicated safe reclamation tooling is not implemented. |
| Remote staging growth | S3 uses bounded anonymous local spooling; native GCS/Azure use verified staging + conditional copy. Configure provider lifecycle and abandoned-upload cleanup; hard provider-side temporary quota enforcement is not implemented. Native provider account tests are outstanding. |
| Jobs / stale completion | Persistent atomic claims and attempt tokens, startup recovery under exclusive authority, retry/backoff/jitter/quotas and per-vault fair claims. Integrity jobs read immutable bodies only and do not overwrite newer notes. No automatic history/blob deletion. |
| CSRF / CORS | Exact origins only, no wildcard; actual requests with unapproved Origin are rejected before mutation, not merely hidden by CORS. Basic/Bearer still required. No cookie-login/JWT trust shortcut or body-controlled roles. |
| Prompt injection | Notes/documents remain untrusted data. This server never interprets note instructions or executes design-document JavaScript. Future MCP must independently enforce scopes/approvals; authentication alone neither decrypts E2EE nor makes note instructions trusted. |
| Supply chain | Pinned Rust toolchain/lockfile, first-party unsafe forbidden, fresh RustSec/deny scans, digest-pinned static distroless image, image/layer verification and secret scans, commit-pinned CI actions. Node/Commonlib/PouchDB dependencies are test-only, lockfile-pinned, no install scripts, separately audited; upstream deprecated test adapter warnings are visible. Scanners do not prove vulnerability freedom. |

## Deployment and acceptance

No public ingress, Funnel, HPA, privileged service container, host network, default password or additional runtime executable. Non-root/read-only rootfs, dropped capabilities, resource limits, private persistent roots. Compose binds host loopback; remote credentials require private Tailscale Serve HTTPS and restrictive ACLs. Kubernetes ClusterIP/NetworkPolicy is internal only; an approved private TLS proxy and matching ingress policy are still needed for remote use. Narrow sample cloud TCP/443 egress to provider ranges or a controlled gateway.

Liveness/readiness are intentionally unauthenticated and disclose only operational availability. Readiness is 204 after initialization, 503 during shutdown. Native TLS termination is not built into the Rust process. Do not send credentials over a remote plaintext connection.

Reference and actual Commonlib/PouchDB fixtures are not GUI/mobile or hardware power-loss certification. Default kind CNI does not enforce NetworkPolicy; policy-aware CNI and tailnet TLS validation remain production gates. Native cloud/provider disaster recovery also requires separately authorized drills. See [results](results.md) for exact evidence and [protocol](livesync-protocol.md) for wire/recovery semantics.
