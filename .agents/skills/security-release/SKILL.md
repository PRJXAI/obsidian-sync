# Security and release checks

1. Read AGENTS.md and the consistency/threat model. All first-party tooling/tests use Rust (`cargo xtask`); never execute Python. Shell scripts only launch Rust. npm/Node remain confined to the pinned upstream JavaScript client bridge. The target is Self-hosted LiveSync; inspect its pinned source contract and test evidence rather than inventing endpoints.
2. Run scripts/check.sh and scripts/check-features.sh. Fix failures, including lints. Never ignore RustSec findings or loosen policy to get green output.
3. Run `cargo xtask test-livesync` and scripts/test-s3.sh; the normal Rust test suite already runs the in-process HTTP fixtures in `tests/couch.rs` (or run `cargo test --locked --test couch` directly). External reference CouchDB is retired by owner request; existing fixtures are not independent differential evidence and must not replace actual client tests against the real Rust server. This is an actual local S3-compatible service, not a MinIO/AWS certification. Native GCS/Azure contract tests require separately authorized disposable credentials; do not use a real account or vault by default.
4. Build `docker build --target build -t obsidian-sync:builder .` and `docker build -t obsidian-sync:local .`; verify the final stage remains Distroless static/nonroot with only the binary added. Run `cargo xtask scan-sources`, `cargo xtask generate-sbom`, then `cargo xtask scan-sbom --sbom-dir .work/sbom` AFTER the final source rebuild, `cargo xtask scan-supply-chain --platform linux/arm64` (amd64 in CI), `cargo xtask verify-release --image obsidian-sync:local --scan-report .work/sbom/runtime.scan.json`. See docs/scanner-pipeline.md: Syft generates native SBOMs, Grype is the sole image vulnerability scanner, and every effective/suppressed match remains counted. The owner's exact 2026-10-30 snapshot may pass as accepted-risk; new/unaccepted findings and inventory/scan errors still block. Trivy, comparison commands and the transition gate are retired by owner request; historical reports are not advisory closure and must not be relabeled clean. CI must reuse the same exported images across scan/integration/SBOM jobs and bind the original archive bytes. Run `cargo test --locked -p xtask`. Public security artifacts contain count/status summaries, not raw reports; preserve raw local reports/ledgers in an owner-approved private archive (destination still pending). Never publish secret matches or provider/tool logs. Record image/config/layer identities, scanner/advisory timestamps, complete source/native inventory, SBOM/materials hashes and unresolved findings. A clean runtime scan is NOT a clean entire supply chain: known accepted upstream findings remain visible, unaccepted/new findings still block, and no severity/advisory scanner suppression is used. Content verification requires trusted reports and is not signing. No scanner proves vulnerability freedom.
5. Run scripts/validate-deployments.sh, scripts/smoke-compose.sh and scripts/smoke-kubernetes.sh. The latter creates its own k3d/K3s cluster with private HOME/kubeconfig and labeled volume, disables default-context updates, and checks persistent identity, writer fencing and complete owned-resource teardown. Never invoke kubectl against the current context. Smoke tests never publish images; a separate publication path needs explicit owner authorization and successful source-bound gates. Require actual Commonlib/PouchDB fixtures (including encrypted replays, bootstrap resets and restart) before accepting readiness 204. GUI/mobile validation is a separate claim. NetworkPolicy needs separate enforcement testing with a policy-aware CNI.
6. Run scripts/benchmark.sh on an otherwise idle machine. Record CPU, RAM, OS, workload, samples, throughput, p50/p95/p99, and peak RSS. Distinguish core measurements from network/plugin performance; three attachment samples are not robust tail statistics.
7. Check backup restoration tests; do not claim a cloud/PVC disaster-recovery drill unless actually performed. Follow maintain-docs to update docs/results.md and acknowledge reviewed source drift.
8. Handoff implemented functionality, executed test results, scan evidence, compatibility status, benchmarks and blocked checks. Do not release production acceptance while protocol/provider/isolation gates remain unmet.
